# Contributing

Thank you for helping. These notes are for anyone preparing for backend interviews.
The most useful help is a **correction**: a wrong fact, a wrong complexity, code that does
not compile, or a broken link.

## How to help

| You found… | Do this |
|---|---|
| A mistake (fact, code, number) | Open an issue with the **Correction** form, or send a pull request with the fix |
| A broken link or image | Open an issue, or fix it in a pull request |
| A confusing explanation | Open an issue and say which sentence was unclear |
| A missing topic | Open an issue first, so we can agree it fits before you write it |

## Rules for changes

1. **Facts must be checkable.** For a number, a version or an API name, add a link to an
   official source (JDK docs, Spring docs, a paper, the database's own docs).
2. **Code must compile and run.** Use Java 17+ unless the note says otherwise. Keep each
   method body on more than one line.
3. **Plain English.** Many readers are not native English speakers. Use short sentences
   and common words. Keep technical terms exact (`volatile`, idempotency, quorum).
4. **Your own words only.** Do not paste text or diagrams from books, paid courses or other
   sites. A short quote with its source is fine.
5. **No private or company information.** Do not add code, names, numbers or stories from
   your employer or any real company system that is not public.
6. **One change per pull request.** Small pull requests are reviewed faster.
